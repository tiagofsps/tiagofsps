### Tiago Pires

Computer Science and Business Management at ISCTE-IUL · Full-Stack Developer at FISTA · Lisbon

I care about how a system works as a whole: whether it solves the right problem, whether it is secure and maintainable, and whether it can actually be delivered and operated. Writing code is part of that, not the whole of it.

At FISTA I work in an Agile team on a system-wide refactor toward Domain-Driven Design, maintain core documentation, and build features on the T3 stack (Next.js, React, tRPC, TypeScript). I have also contributed to PostgreSQL data modelling and to CI pipeline logging — the part that tells you a deployment went wrong matters as much as the deployment itself.

My interests run toward cloud, cybersecurity, QA, and governance, risk and compliance: the disciplines that decide whether something is fit for purpose. I am building experience in those areas rather than claiming it. What I bring now is an unwillingness to call something done before I understand why it works.

#### Selected work

**[hunting-fishing-store](https://github.com/tiagofsps/hunting-fishing-store)** — Spring Boot 4 / Java 21 REST API for an e-commerce backend. JWT access and refresh tokens with Redis-backed revocation, role-based access control, catalog, cart, checkout, payments, coupons and newsletter. Flyway migrations, OpenAPI documentation, and unit, controller, repository and Testcontainers integration tests.

**[hunting-fishing-store-web](https://github.com/tiagofsps/hunting-fishing-store-web)** — React 19 + TypeScript storefront for the same domain: catalog, cart, checkout and an admin console, with 414 tests and a coverage gate in CI.

**[siteledger](https://github.com/tiagofsps/siteledger)** — Django and PostgreSQL operations manager for small construction companies: projects, suppliers, purchases, and an append-only stock ledger where the history is the record, not a summary of it.

**[is-kahoot](https://github.com/tiagofsps/is-kahoot)** — concurrent client-server quiz game in Java. TCP sockets, a thread per client, and a hand-written team barrier, with the protocol and the threading model kept deliberately small enough to reason about.
